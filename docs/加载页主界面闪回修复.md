# 加载页到主界面的闪回修复

日期：2026-10-26

## 根因

加载页的 closed 回调无条件显示主窗口，而主窗口此时仍停在登录路由。原 close-loading-window 在通知渲染进程之前就销毁了加载页，导致先显示一帧登录页，再异步跳转主界面。

## 修复

1. 点击“进入聊天”只通知隐藏的主窗口，保留加载页。只接受加载窗口本身发出的完成通知。
2. 登录、确认登录和注册完成入口在路由进入 /main 后等待 Vue nextTick，确保主界面 DOM 已挂载。
3. 主窗口先调整到主界面尺寸，再通过 capturePage 的 stayHidden 选项确认隐藏页面完成一次合成。确认过程不显示窗口，也不保存用户画面。
4. 合成结束后显示主窗口，随后清理并销毁加载页。清理时先清除 loadingWindow 引用，closed 回调不会再触发多余显示。
5. 加载页意外关闭时仍恢复来源窗口；绘制确认异常时记录警告并展示已挂载的主界面，避免加载页永久卡住。

未添加固定延时，也未永久关闭窗口的后台节流。

## 验证

- npm run build 通过，包含类型检查、ESLint 和 9 个测试入口、95 项内部回归；保留原有未使用变量和字体资源提示。
- 新增 7 项窗口交接回归：提前显示防护、尺寸/绘制/显示/关闭顺序、closed 防重复、异常关闭恢复、通知来源校验、已有账号入口和绘制失败恢复。
- npm run test:handoff 通过。使用真实 Vue 登录页、路由、生产 preload 和 Electron 隐藏页面合成，接口与数据库为隔离假数据。测试在登录帧放红色标记，主界面挂载后改绿，并检查首次交接截图的像素，确认实际合成帧已更新。
- 实际记录的顺序为 hide-main → show-loading → paint-main → show-main → closed-loading，主窗口只显示一次。
- 测试拦截 OS 层 show 以保持后台运行，验证的是实际隐藏合成帧与显示调用顺序，不代表真实账号认证或数据库链路验收。

本次修改了主进程 IPC，需完整重启 Electron 后检查。

# 加载页到主界面的闪回修复

更新：2026-10-27

## 当前交接行为（2026-10-27）

用户实测发现点击“进入聊天”后仍卡在加载窗口。源码中 `enterMain` 等待隐藏窗口的 `capturePage`，只处理拒绝，没有处理一直不返回的情况；手动关闭加载窗口时 `closed` 恢复主窗口显示，才使等待继续。这是初版隔离验证未覆盖的实际窗口边界。

- 加载页出现后开始计时，10 秒自动进入；“进入聊天”始终可用，可提前跳过等待，不必等数据同步结束。
- 手动点击和计时结束共用主进程交接函数，一次加载只发出一次进入通知；交接或窗口关闭时清理计时器。
- 登录和注册页面先监听交接通知，再创建加载页，避免快速点击时漏掉事件。
- 保留 `/main` 路由挂载与 `nextTick`。交接绘制时临时关闭后台节流，截图确认最多等待 500 毫秒，随后恢复节流、显示主窗口并销毁加载页。不会固定等待 500 毫秒，截图提前完成即继续；不会把截图作为永久阻塞条件。
- WS 连接在窗口显示后建立，连接不阻止窗口交接。
- 跳过后主进程继续原有初始化。落库后通知主界面从 SQLite 刷新会话、联系人和当前聊天记录，保留期间收到或发送的消息；同步结果属于旧账号时丢弃。
- 同步失败仍保留原有失败提示，不写初始化成功记录，下次首次初始化仍可重试。

本轮按用户要求未运行测试、构建或实际窗口验证。只核对源码；现有交接测试的隔离环境补齐计时器和后台节流接口，未执行。需完整重启 Electron 后人工检查：立即点击跳过、等待 10 秒自动进入、同步慢于 10 秒后列表补齐，以及重复点击不重复交接。

以下保留 2026-10-26 初版修复与当时的隔离验证记录，不代表本轮代码已通过这些测试。

## 根因

加载页的 closed 回调无条件显示主窗口，而主窗口此时仍停在登录路由。原 close-loading-window 在通知渲染进程之前就销毁了加载页，导致先显示一帧登录页，再异步跳转主界面。

## 修复

1. 点击“进入聊天”只通知隐藏的主窗口，保留加载页。只接受加载窗口本身发出的完成通知。
2. 登录、确认登录和注册完成入口在路由进入 /main 后等待 Vue nextTick，确保主界面 DOM 已挂载。
3. 主窗口先调整到主界面尺寸，再通过 capturePage 的 stayHidden 选项确认隐藏页面完成一次合成。确认过程不显示窗口，也不保存用户画面。
4. 合成结束后显示主窗口，随后清理并销毁加载页。清理时先清除 loadingWindow 引用，closed 回调不会再触发多余显示。
5. 加载页意外关闭时仍恢复来源窗口；绘制确认异常时记录警告并展示已挂载的主界面，避免加载页永久卡住。

初版未添加固定延时，也未永久关闭窗口的后台节流；当时没有为合成等待设置上限。

- npm run build 通过，包含类型检查、ESLint 和 9 个测试入口、95 项内部回归；保留原有未使用变量和字体资源提示。
- 新增 7 项窗口交接回归：提前显示防护、尺寸/绘制/显示/关闭顺序、closed 防重复、异常关闭恢复、通知来源校验、已有账号入口和绘制失败恢复。

# 截图、双主题与界面优化记录

日期：2026-10-26

## 已完成的行为

| 用户需求 | 实现结果 |
| --- | --- |
| 快速截图、大图报错或卡住 | 主进程在抓屏前占用会话，拒绝重复打开；拖动只更新选框，不复制像素；保存仅传选区和视口尺寸，由主进程裁剪原图并异步写盘。 |
| 截图失败后无法恢复 | 取消、加载失败、超时、渲染进程退出和保存失败统一清理会话并恢复来源窗口；保存期间取消不会让旧任务关闭下一次截图。 |
| IM 加载动画特色与速度 | Canvas 按 I 与 M 的四笔共五笔依次填充，每笔 1.5 秒，总长约 7.5 秒。数据提前完成不会跳至最终帧；数据已就绪时可手动进入聊天。 |
| 亮暗两种玻璃主题 | 亮色使用雾蓝分层，暗色使用蓝灰分层；保留用户壁纸。主题变量集中在 public/theme.css，Element Plus 变量由 variables.css 映射。 |
| 只在介绍界面切换主题 | 会话、联系人、收藏未选择内容时复用 ChatWelcome。只在那里显示主题按钮；主进程限制 theme:set 的调用路由。 |
| 介绍界面恢复拖拽、不需要跳转按钮 | 空白介绍区域设置为窗口拖拽区，主题按钮单独设为可点击区；移除重复导航和最近会话按钮。 |
| 输入框不要蓝色边框 | 全局清除原生输入、Element Plus 输入、选择控件的边框、焦点 outline 和 box-shadow；清除 AI 输入区与钱包金额输入外层的焦点光圈。 |
| 登录与注册风格不同 | 保留原有青蓝、粉紫边框动画及各自壁纸，不统一成同一种账号页外观。 |
| 钱包界面需要优化 | 重做余额卡片、两列操作区、账单筛选及流水、空状态、充值和提现弹窗，适配亮暗主题；保留现有资金请求逻辑。 |

## 主题与窗口

- src/main/Util/theme.js 在启动时读取 appearanceTheme，并设置 Electron nativeTheme.themeSource。
- 切换后写入现有 electron-store，更新所有存活窗口的背景并广播主题；新窗口继承当前模式。
- preload 在首屏绘制前同步取得模式，并为 Vue、截图、加载等窗口更新 data-theme。
- 去掉整个主窗口的 opacity: 0.98，避免桌面或编辑器文字穿透；玻璃效果来自应用内壁纸与面板的 backdrop-filter。
- 移除会在构建产物中造成 Vue、Element Plus 共享依赖循环的手动分包，让 Rollup 自动生成共享块和路由分包。实际构建页面已纳入验证。

## 验证边界与运行方式

- 8K 使用合成图验证 NativeImage 裁剪；系统抓屏 API 在当前一个显示器上成功返回图像，未在真实 8K 屏幕或多物理屏组合上做操作验收。
- 主题持久化经过主进程逻辑回归，页面重载与跨窗口同步经过实际渲染验证；未改写真实账号设置文件进行整机重启测试。
- 钱包视觉检查使用测试余额与账单，不代表充值、提现后端链路已重新验收；原有转账、收款入口的业务状态维持原实现。
- 构建保留原有 iconfont woff/woff2 资源提示，没有在本次改动中替换字体资产。
- 主进程和 preload 都有更新，需完整退出并重新启动开发进程，再验收截图和主题；仅靠页面热更新不足以加载全部改动。

复现：先运行 npm run build，再运行 npm run test:desktop。后者会输出临时预览图目录并自动关闭测试窗口。

# 代码检查与回归测试

## 日常使用

在项目根目录运行：

```bash
npm run check
```

它依次执行 ESLint、类型检查和回归测试，任一环节失败都会返回非零退出码。`npm run build` 会先执行同一检查，再构建主进程、预加载脚本和渲染进程；各平台打包命令沿用这个入口。

| 命令 | 用途 |
| --- | --- |
| `npm run lint` | 检查 JS、TS、Vue 代码，保留未使用项警告 |
| `npm run typecheck` | 严格检查渲染进程 TS、Vue 脚本和模板，不输出编译文件 |
| `npm test` | 自动发现并执行 `tests/*.test.cjs`，单文件超时 30 秒 |
| `npm run check` | 依次执行上述三项检查 |
| `npm run build` | 检查通过后执行 Electron Vite 生产构建 |
| `npm run format:check` | 单独检查格式，不改写源码，不属于构建门槛 |

工具依赖在 `devDependencies` 中。如果安装环境省略开发依赖，需要用 `npm install --include=dev` 安装。项目当前使用 Node 22.21.1。

## 原配置与现在的区别

| 原来的情况 | 现在的处理 |
| --- | --- |
| Vue 解析器没有连接 TS 解析器，带类型语法的文件出现解析错误 | Vue 外层保留 `vue-eslint-parser`，脚本使用 TS 解析器；独立 TS 也进入 ESLint |
| 缺少独立类型检查，Vite 转译成功容易被当成类型正确 | 增加 `vue-tsc --noEmit`，保持 `strict: true`，检查脚本及模板 |
| 通配 `.js`、`.vue` 声明和部分第三方库的 `any` 掩盖类型信息 | 删除这些兜底声明，使用实际模块推断及 DPlayer、Masonry 的类型包 |
| 格式告警混入正确性检查 | Prettier 独立运行；ESLint 使用 Vue essential 规则检查正确性，未使用项单独保留为警告 |
| 关键故障主要靠手动复现，构建前没有统一验证 | 保存实际源码的回归用例，统一检查并接入构建 |

检查实际暴露的问题也已修复，包括群头像路径对 `const` 重新赋值、好友申请代码缺少语句边界、路由导入大小写不一致、直接修改会话 props、API 响应类型与拦截器解包结果不一致，以及不同格式消息时间直接相减。

## 检查范围

ESLint 覆盖主进程、预加载脚本、渲染进程、配置及测试中的 JS、TS、Vue；忽略依赖与 `out`、`dist` 产物。Vue 中仍有 JS 脚本，因此保留了 Vue 的未定义变量检查。

类型检查包含渲染进程当前全部 26 个 TS 文件（含声明文件）和 66 个 Vue 文件。`allowJs` 用于推断导入的 JS 模块，未开启整个 JS 项目的 `checkJs`；主进程和预加载脚本现有 JS 由 ESLint 检查，不能据此宣称其拥有完整静态类型保障。现有源码中的局部 `any` 也没有全部消除。

`tests/checks.test.cjs` 会验证 TS 和 Vue 能被 ESLint 解析、未定义变量及 async Promise 执行器仍会报错、全部渲染进程 TS/Vue 文件被纳入类型检查。它还检查 `tests/fixtures/typecheck` 中故意写错的 TS、Vue 脚本及模板，确认类型检查确实失败。这些预期失败的夹具有独立配置，不进入应用类型检查；不要把它们改成正确代码。

## 回归场景

| 文件 | 场景数 | 主要内容 |
| --- | --- | --- |
| `downloadFile.test.cjs` | 23 | HTTP 状态、Range 校验、暂停续传、重定向、断流、文件内容完整性 |
| `messageAck.test.cjs` | 7 | 历史前插、删除、迟到及重复 ACK、保存内容、其他待确认消息 |
| `messageCache.test.cjs` | 14 | 超过 500 条加载历史、离开会话裁剪、待确认消息保护、迟到分页隔离 |
| `refreshToken.test.cjs` | 8 | 网络失败后重试、并发共享刷新、失败请求全部结束、HTTP 及业务失败处理 |
| `workspaceTools.test.cjs` | 12 | 文件搜索、读取、写入、目录列表和命令输出处理 |
| `checks.test.cjs` | 6 | 解析、规则生效、类型检查范围及预期失败验证 |
| 合计 | 70 | 6 个测试文件 |

测试读取实际实现，并隔离 Electron IPC、计时器、请求适配器等外部依赖；下载测试使用本地 HTTP 服务和临时文件。它们用于防止已知故障再次出现，不代表全项目行为或全部代码分支已覆盖。

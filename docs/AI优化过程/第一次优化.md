## 执行的 12 项优化

### Vue 响应速度（6 项）

#### 1. Moments 帖子列表 `deep: true` → `shallow` watch
- **文件**: `src/renderer/src/views/moments/Moments.vue`
- **问题**: 对 150 条帖子数组做 `{ deep: true }` watch，每次点赞（修改 `post.liked`）Vue 会 `traverse()` 遍历所有帖子的所有属性，然后触发 Masonry 全量重排
- **改动**: `watch(postList, ..., { deep: true })` → `watch(() => postList.value.length, ...)`
- **效果**: 点赞不再触发深度遍历 + Masonry 重建，只在帖子增删时重排

#### 2. ChatFileView 8 个 computed → 2+6 派生
- **文件**: `src/renderer/src/components/ChatFileView.vue`
- **问题**: 8 个 computed 各自调用 `getFileUploadUpdateInfo(props.fileId)` 或 `getFileDownloadInfo(props.fileId)`，每次重新计算做 8 次独立 Map 查找
- **改动**: 提取 `uploadInfo` / `downloadInfo` 两个 computed，其余 6 个从中派生
- **效果**: 每次刷新从 8 次 Store 查找降到 2 次

#### 3. 移除 6 处 `Date.now()` 图片缓存破坏
- **文件**: `UserList.vue` `UserConversationList.vue` `GroupInfo.vue` `GroupApply.vue` `ChatHeaderGroupDrawer.vue`
- **问题**: `<img :src="avatar + '?t=' + Date.now()">` 每次渲染生成新 URL，浏览器缓存完全失效
- **改动**: 移除所有 `+ '?t=' + Date.now()`
- **效果**: 头像图片正常缓存，列表滚动/状态更新不再重复下载

#### 4. 会话列表排序缓存 dirty flag
- **文件**: `src/renderer/src/views/user/UserConversationList.vue`
- **问题**: `computed` 中每次访问都 `Object.values(conversationMap).sort(...)`，任何会话属性变化都触发全量重建+排序
- **改动**: 添加 `sortedConversations` shallowRef + `sortDirty` flag，通过 `$subscribe` 标记失效
- **效果**: computed 多次访问只返回缓存，store 变更后才重排一次

#### 5. 在线状态从 friendInfoMap 剥离
- **文件**: `src/renderer/src/stores/modules/ContactListStore.ts` `UserList.vue` `wsHandlers.js`
- **问题**: 好友上下线时修改 `friendInfoMap[id].isOnline`，导致 `friendListArr` computed 全量重建
- **改动**: 在线状态仅维护在 `onlineUserIds: Set<string>` 中，模板直接读 Set
- **效果**: 好友上下线不再触发联系人列表全量重渲染

#### 6. 聊天消息 `v-memo` 跳过不变消息
- **文件**: `src/renderer/src/views/chat/ChatBase.vue`
- **问题**: 500 条消息全部渲染到 DOM，新消息到达时整个列表做 v-for diff
- **改动**: 添加 `v-memo="[message.id, message.sendStatus, message.content, ...]"`
- **效果**: 新消息到达只 diff 变化的条目，其余跳过

### Electron 内存/主进程（6 项）

#### 7. 下载进度 IPC 100ms throttle
- **文件**: `src/main/File/downloadFile.js`
- **问题**: HTTP stream 的 `data` 事件在 OS 缓冲区粒度触发（16-64KB），100MB 下载可产生 1600+ 次 `webContents.send('download-progress')`
- **改动**: 提取 `sendProgressThrottled()` 函数，用 `lastProgressSend` Map 按 fileId 限流 100ms
- **效果**: IPC 频率从 ~1600/s 降到 ~10/s

#### 8. Piscina worker 线程数封顶 4
- **文件**: `src/main/File/poolConfig.js`
- **问题**: `os.cpus().length` 在 16 核机器上创建 16 个 worker × 200MB 堆上限 = 3.2GB 峰值
- **改动**: `Math.min(os.cpus().length, 4)`
- **效果**: 峰值内存从 ~3.2GB 降到 ~800MB

#### 9. WebSocket 广播合并两次 `getAllWindows()` 为一次
- **文件**: `src/main/websocket.js`
- **问题**: 每条 WS 消息先在第 228 行遍历所有窗口发 `play:messageSound`，再在第 273 行遍历发 `ws:receive`
- **改动**: 合并为一次 `getAllWindows()`，在单次 forEach 中同时发送 `ws:receive` 和 `play:messageSound`
- **效果**: 每条 WS 消息减少一次同步 IPC 调用 + 一次 forEach

#### 10. `fileChunkStatusMap` 内存泄漏修复
- **文件**: `src/main/File/createWorkerProcess.js`
- **问题**: Worker 中按 fileId 存储的 `chunkStatusArray`（长度 = chunkCount）只增不删，上传完成后残留
- **改动**: 在 `checkAndMerge` 成功和 `readStream.on('error')` 两处添加 `fileChunkStatusMap.delete(fileId)`
- **效果**: 上传任务的分配状态在完成后立即释放

#### 11. `shareStorePlugin` 100ms 防抖
- **文件**: `src/renderer/src/stores/plugins/shareStorePlugin.ts`
- **问题**: 每次 `conversationMap` 属性变化都 `JSON.stringify(store.$state)` 完整序列化 + IPC 广播
- **改动**: 添加 100ms debounce timer，合并高频变更到一次广播
- **效果**: 批量更新时减少 5-10 倍 IPC 序列化次数

#### 12. 暂停下载清理 `activeDownloads` Map
- **文件**: `src/main/File/downloadFile.js`
- **问题**: 暂停下载时 `activeDownloads` 条目不被删除，用户暂停多个后 Map 持续增长
- **改动**: 暂停时删除 `activeDownloads` 条目，恢复时通过 `existing` 变量重新创建
- **效果**: 暂停行为不再泄漏下载状态对象
